# Лабораторна №5 — Flask-WTF, TinyDB та CRUD товарів

Flask-застосунок із резюме й контактами Михайла Венгриновича, головною сторінкою, привітаннями, профілем, cookies і темою. Лабораторна №5 додає контактну Flask-WTF форму, глобальний CSRF-захист, TinyDB, CRUD товарів та зображення. Збережено простий екземпляр `app` і наявні Blueprint; SQLAlchemy та Flask-Login не використовуються.

## Запуск у PowerShell

Із кореня проєкту, використовуючи наявне `.venv`. Локальний `.env` із випадковим `SECRET_KEY` уже налаштовано та виключено з Git. `config.py` читає його через наявний `python-dotenv`; змінна середовища `SECRET_KEY` має пріоритет.

Встановлення потрібних залежностей:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Додано Flask-WTF/WTForms для форм, TinyDB для JSON-сховища, email-validator для перевірки email та Pillow для перевірки вмісту зображень. Попередні залежності збережено.

Для нової копії проєкту без `.env` ключ можна створити командою, яка не виводить його й відмовляється перезаписувати наявний файл:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; from pathlib import Path; Path('.env').open('x', encoding='utf-8').write('SECRET_KEY=' + secrets.token_hex(32) + '\n')"
```

Запуск сервера:

```powershell
.\.venv\Scripts\python.exe -m flask run
```

`.flaskenv` містить `FLASK_APP=run.py`, `FLASK_DEBUG=1`, `FLASK_RUN_PORT=8080`. Альтернативний прямий запуск також використовує порт 8080:

```powershell
.\.venv\Scripts\python.exe run.py
```

Зупинка сервера — `Ctrl+C`. Справжній ключ не зберігається в коді. `.venv`, `.env`, кеш Python, методички `lab3.pdf`–`lab5.pdf`, тимчасові файли, робоча база, логи, завантаження та скріншоти виключені з Git. `.vscode/` — незмінені налаштування користувача поза комітами.

Демонстраційні дані входу: **misha / lab4pass**. Це фіксовані навчальні значення, не справжній обліковий запис. Пароль не зберігається в сесії.

## Контактна форма

Клас `ContactForm` розміщено в `app/forms.py`. Ім’я обов’язкове, 4–10 символів; email обов’язковий і має коректний формат. Телефон можна залишити порожнім, а заповнений має відповідати `+380` і дев’яти цифрам. Тема вибирається зі списку «Запитання / Співпраця / Відгук». Повідомлення обов’язкове, максимум 500 символів.

Дані дописуються в `logs/contacts.log` у UTF-8: один JSON-запис на рядок, із часом у UTC. Переноси рядків усередині повідомлення екрануються JSON. CSRF-токен не записується. Після успіху — flash про **збереження**, а не надсилання email, та redirect на ту саму GET-адресу. Оновлення сторінки не дублює запис. Помилка валідації залишає введені значення й показує помилки біля полів; помилка запису повертає 503 без повідомлення про успіх. Пошта не підключена.

## Товари, сховище й зображення

- Робоча база: `data/products.json`; шлях у `config.py` визначений від кореня проєкту, незалежно від поточної папки запуску. База відкривається на час операції. Каталоги `data/`, `logs/` та `app/products/static/uploads/` створюються автоматично при першому використанні.
- Під час першого створення файла бази додаються Laptop, Phone, PC із точними описами лабораторної №3. Початкова кількість — 0, зображення відсутні. Наявний порожній файл/порожня таблиця не запускають повторне наповнення; видалені товари не відновлюються.
- Таблиця `products` містить `id`, `name`, `content`, `price`, `category`, `quantity`, `image`, `created_at`. Лічильник у `metadata` забезпечує нові id без повторного використання після видалення. Дата створення — ISO 8601 у UTC; редагування її та id не змінює.
- Ціна перевіряється як `Decimal`, а в JSON записується рядком із двома знаками після крапки. Допустимо 0.01–999999999.99; більше двох десяткових знаків, нуль, від’ємні значення, NaN та Infinity відхиляються. Валюту не вигадано.
- Назва нового/редагованого товару — 3–120 символів; опис — до 5000 символів, поле 5×40; категорії — ноутбуки, телефони, комп’ютери. Кількість — ціле число від 0. Початковий товар `PC` збережений за попередньою лабораторною; при редагуванні назва має відповідати новому мінімуму 3 символи.
- Зображення необов’язкове. Дозволено PNG/JPG/JPEG до 5 МБ; перевіряються розширення, справжній формат і читабельність через Pillow. Загальний HTTP-запит обмежено 6 МБ з урахуванням multipart-обгортки; перевищення дає зрозумілу сторінку 413.
- Файл отримує UUID-ім’я в `app/products/static/uploads/`; у базі зберігається лише `uploads/<uuid>.<extension>`. Його віддає маршрут `products.uploaded_image` під `/products/static/uploads/…`. Стандартний static-маршрут Blueprint віддає SVG-заглушку. Якщо зображення відсутнє або файл недоступний, показується заглушка.
- Редагування без нового файла зберігає старе зображення. При заміні старий UUID-файл видаляється тільки після успішного запису товару. При помилці запису новий файл прибирається; сторонні файли та шляхи поза uploads не видаляються. Після видалення товару його власне зображення також прибирається.
- TinyDB використовується як просте локальне сховище одного процесу Flask; операції в цьому процесі захищає `RLock`. Багатопроцесний запис та транзакції промислової СУБД не реалізовано.

## Flask-WTF і CSRF

`FlaskForm` об’єднує поля, дані й валідатори; `validate_on_submit()` перевіряє POST. Спільний Jinja-макрос `render_field` у `components/form_fields.html` створює підпис, Bootstrap-поле та блок помилок для обох форм.

`CSRFProtect(app)` увімкнений глобально. Форми Flask-WTF використовують `hidden_tag()`, а форми входу, профілю, cookies, теми й видалення товару містять прихований `csrf_token`. Відсутній, неправильний або застарілий токен дає HTTP 400 без запису даних. Захист не вимикається в тестах: клієнт отримує справжній токен через GET.

PRG означає Post/Redirect/Get: після успішного POST сервер перенаправляє браузер на GET. CRUD — Create, Read, Update, Delete: створення, перегляд, редагування й видалення записів. TinyDB надає ці операції над JSON-файлом без SQLAlchemy.

Документація: [Flask-WTF CSRF](https://flask-wtf.readthedocs.io/en/1.2.x/csrf/), [TinyDB](https://tinydb.readthedocs.io/en/latest/usage.html).

## Поведінка cookies й теми

- Для навчальних cookies зарезервовано префікс `lab4_`. Ключ `note` створює `lab4_note`; якщо префікс уже введено, він не дублюється. Ім’я без префікса містить 1–40 латинських літер, цифр, дефісів або підкреслень.
- Значення може бути порожнім; максимум — 512 байтів UTF-8, без керівних символів. Термін дії — ціле число від 1 до 31536000 секунд. Сервер перевіряє ці умови незалежно від HTML-форми та показує зрозумілі помилки.
- Cookie сесії (`session`) не можна перезаписати формою додавання. Cookie `lab4_theme` змінюється лише через вибір дозволеної теми. Перевіряється також назва сесії з конфігурації.
- Cookies створюються для поточного хоста з `Path=/`, `HttpOnly` і `SameSite=Lax`. `max_age` задає строк зберігання; браузер отримує `Max-Age` і `Expires`. Таблиця показує всі cookies з `request.cookies`, включно із сесією та можливими сторонніми cookies цього хоста.
- Після додавання або видалення виконується перенаправлення: новий GET уже містить оновлені cookies. Для видалення можна вказати ключ із таблиці або ключ без `lab4_`.
- Кнопка «Видалити всі cookies застосунку» видаляє cookies з префіксом `lab4_`, які надійшли в запиті, та cookie сесії. Сторонні cookies навмисно залишаються — це зазначено в інтерфейсі. Cookies не ізолюються за портами, тому використано префікс. Застосунок створює і видаляє cookies лише з `Path=/`, без `Domain`; сторонні cookies з іншими шляхами чи доменами він не очищує.
- Видалення `session` окремо або всіх cookies застосунку очищує попередню сесію та повертає на login. Повідомлення береться з фіксованого списку за параметром `notice`. Від лабораторної №5 форма входу створює **нову анонімну сесію для CSRF**, без імені користувача. Це прямо зазначено в повідомленні; стан входу не відновлюється.
- Звичайний вихід видаляє стан входу, але зберігає навчальні cookies й тему. Flash про вихід може тимчасово створити анонімну cookie сесії; вона не містить користувача.
- Тема зберігається в `lab4_theme` на 365 днів і переживає закриття браузера, якщо користувач не очищує cookies. За відсутності або некоректного значення використовується `light`. Умовний клас і Bootstrap `data-bs-theme` змінюють лише сторінку профілю, включно з формами, таблицею та повідомленнями.

## Коротко для захисту

- `request.form` — значення полів надісланої POST-форми; `.get()` дозволяє обробляти відсутні поля без помилки.
- `session` — стан між запитами. Стандартна сесія Flask зберігається в підписаній cookie; `SECRET_KEY` захищає підпис від підробки, але не шифрує вміст. Тут зберігається ім’я користувача, не пароль.
- `flash(message, category)` — одноразове повідомлення. `get_flashed_messages(with_categories=true)` у `base.html` відображає його як Bootstrap alert відповідного кольору.
- `response.set_cookie()` додає заголовок відповіді для створення або зміни cookie у браузері.
- `response.delete_cookie()` надсилає cookie з терміном дії, що минув; ім’я та шлях мають відповідати створеній cookie.
- `redirect(url_for(...))` після POST повертає браузер на GET-сторінку й оновлює таблицю без повторного надсилання форми.
